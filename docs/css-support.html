CSS support

Donkeh parses real stylesheets with a CSS engine rather than translating a subset at build time. This page tracks the 168 property names the resolver recognises, the selector features that participate in matching, and the fastest way to get a CSS bug fixed.

Revision column Each property currently points at the previous framework commit, a68256d. That is a deliberate placeholder until per-property history is backfilled: it identifies the support snapshot, not the exact commit that first added each property.

Selectors and at-rules

The engine supports type, class, id, universal and attribute selectors, plus descendant, child, adjacent-sibling and general-sibling combinators. Specificity, source order and cascade layers decide the winner.

FeatureStatus
Interaction and state pseudo-classes:hover, :focus, :active, :focus-visible, :checked, :disabled, :enabled, :required, :read-only and structural selectors.
Logical pseudo-classes:not(), :is(), :where() and :has() are recognised but flagged as unsupported by the matcher. The native host expands simple :is(a, b) selector lists before parsing, which keeps icon-font stylesheets working.
Pseudo-elements::before and ::after generate a box when their resolved content is a string. CSS hexadecimal string escapes such as \f0c9 are decoded. ::selection is matched and its background-color (or the colour part of background) styles the text highlight; color is stored on the computed style for hosts that paint selected glyphs themselves. Other pseudo-elements are ignored.
Conditional at-rules@media, @supports and @container gate matching. @layer participates in the cascade.
Animations@keyframes and @-webkit-keyframes are parsed; transitions and animations run through the style resolver.
ImportsThe data engine only records @import. The native host fetches HTTP, file and data URLs, inlines them and resolves relative URLs against the declaring stylesheet. The browser host lets the browser load them.

Registered properties

The table lists every property name currently mapped to a CssProperty. A registered name can still have partial value support, so include the exact value in a bug report.

Support is Supported when the resolver writes a computed value that a running stage consumes, Partial support when only part of the syntax changes output, and Not supported when the name or value is parsed but nothing downstream reads it yet. Used by names the stage that consumes the computed value: LayoutLab for layout, text and paint instructions, GLRenderer for GPU drawing, Windowing for input, scrolling, native window behaviour and media, DataEngine for cascade processing, and Inspector for animation inspection.

Reporting a CSS bug

Use the CSS bug report form. It asks for the property and revision, host, pipeline stage, minimal UI tree, minimal CSS, expected and actual rendering, and reproduction steps. That context is usually enough to turn a visual complaint into a failing layout or paint test.

Make the reproduction small One component, one stylesheet, no unrelated framework code. If the bug only appears with other rules present, include the smallest set that still triggers it. A screenshot plus a computed-style or layout dump is worth more than a long description.

Reproduction skeleton

using Donkeh.Hosting;
using Donkeh.UILab;
using static Donkeh.UILab.HtmlHelper;
using static Donkeh.UILab._;

[AppRoot(Width = 800, Height = 600, Title = "CSS repro")]
public sealed class App : Component
{
    public override Node Render() =>
        Div(new() { ClassName = "box" },
            Span(new() { ClassName = "label" }, Text("Hello")));
}
.box {
    display: grid;
    grid-template-columns: 1fr 1fr;
}

.label {
    color: rebeccapurple;
}

Replace the smallest relevant rule and attach the actual result. If the problem needs a specific font, image, viewport or platform, say so in the environment and notes fields.
