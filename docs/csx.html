CSX syntax

You love JSX in JavaScript and TypeScript? Here is the same experience in .NET. CSX lets you build a full UI framework with markup-like components, real CSS and a reconciled tree - and it is entirely optional, with a plain-C# fallback for every example.

Optional JSX-like Source maps IDE support

What CSX is

A .cx file is a C# file with one addition: JSX-style elements such as <Header /> or <div className="app">...</div>. Element tags are lowercase, as in HTML; component tags are PascalCase, as in React. The CSX toolchain transforms those elements into the ordinary _.H, _.C and _.F calls you would otherwise write by hand, then compiles the result as normal C#.

The CSX project lives at github.com/barely-sentient/csx. Donkeh itself stays unchanged; CSX is a separate, optional layer on top.

Setup guide

  1. Install the CSX command-line tool.
  2. Install the matching IDE plugin for VS Code or Rider.
  3. Add a csx.json to your project (the language server creates one automatically).
  4. Write .cx files and run csx run.
dotnet tool install --global CSX.CliTool --version 1.0.1

# Optional: install the IDE plugin
csx enable vscode
# or
csx enable rider

# Create a CSX project (the default)
donkeh new project MyApp
cd MyApp
donkeh run

The csx tool is published to NuGet as CSX.CliTool. The IDE plugins are published as GitHub release assets, so csx enable downloads the version that matches the running CLI.

Project configuration

csx.json sits in the project root and configures the transformer. The defaults match Donkeh's helper class: 

{
  "FrameworkHtmlClass": "_",
  "FrameworkHtmlClassMethod": "H",
  "FrameworkComponentMethod": "C",
  "FrameworkFragmentMethod": "F",
  "GeneratedFileOutput": "src/generated"
}

GeneratedFileOutput controls where the transformed C# is written. Using src/generated keeps the output inside the project so a plain dotnet run compiles it automatically.

A component in CSX

The same component, first in CSX, then as the plain C# it compiles to. 

using Donkeh.UILab;

namespace Components;

public class HeaderProps : Props { }

public class Header : Component<HeaderProps>
{
    public override Node Render() =>
        <header className="header">
            <h1>My Application</h1>
        </header>;
}
using Donkeh.UILab;

namespace Components;

public class HeaderProps : Props { }

public class Header : Component<HeaderProps>
{
    public override Node Render() =>
        _.H("header", new() { ClassName = "header" },
            _.H("h1", null, "My Application"));
}

Using a component

using Donkeh.Hosting;
using Donkeh.UILab;
using Components;

namespace DonkehCSXTest;

[AppRoot(Width = 1000, Height = 700, Title = "DonkehCSXTest")]
public sealed class App : Component
{
    public override Node Render() =>
        <Header />;
}

The CSX transformer rewrites <Header /> into _.C<Header, HeaderProps>(new() { }). The generated file is written to src/generated and compiled with the rest of the project.

Fallback: plain C#

If you do not want to use CSX, write the same calls directly. Nothing else changes: the framework, the hosts and the CSS engine are identical. 

using Donkeh.UILab;

namespace Components;

public class HeaderProps : Props { }

public class Header : Component<HeaderProps>
{
    public override Node Render() =>
        _.H("header", new() { ClassName = "header" },
            _.H("h1", null, "My Application"));
}
using Donkeh.Hosting;
using Donkeh.UILab;
using Components;

namespace DonkehCSXTest;

[AppRoot(Width = 1000, Height = 700, Title = "DonkehCSXTest")]
public sealed class App : Component
{
    public override Node Render() =>
        _.C<Header, HeaderProps>(new() { });
}

How it works

  • Parser: tokenises .cx files and distinguishes JSX tags from C# generics.
  • Transformer: rewrites JSX into configurable C# method calls and writes a source map next to each generated file.
  • Language server: transforms .cx files on the fly and proxies requests to the C# language server, mapping positions back through source maps. VS Code and Rider use it for IntelliSense, diagnostics and navigation.
  • Generated output: .generated.cs files are ordinary C# and are compiled by the normal SDK glob.

Running and building

# Transform .cx files and run
donkeh run

# Equivalent direct CSX commands
csx run
csx build

# Classic flow (generated files already present)
dotnet run

donkeh run delegates to csx run for CSX projects, including framework roots where it transforms the library before running the test container. csx run transforms every .cx file first, then invokes dotnet run on the project. csx build does the same with dotnet build.

Editor plugins

Install the matching plugin for your editor with the CSX CLI. The plugin version is matched to the CLI version automatically. 

csx enable vscode
csx enable rider

The plugins download from the CSX GitHub releases. If you prefer a local build, point the extension settings at your CSX.CliTool output instead.

Donkeh is frozen at this point The Donkeh engine itself is complete; CSX is the recommended way to author components going forward. Existing plain-C# projects keep working unchanged.
