Routing, route values and setPage

The router is a small, host-agnostic path store. It decides which route content is rendered and exposes the current path, the values captured by the matching route and a setPage action through context. It does not touch a URL bar, browser history or the network.

A route table

Import Donkeh.UILab.Routing for the factories and wrap the app in AppRouter. AppRoutes renders the first matching Route. 

using Donkeh.Hosting;
using Donkeh.UILab;
using static Donkeh.UILab.HtmlHelper;
using static Donkeh.UILab.Routing;

[AppRoot(Width = 1000, Height = 700, Title = "My app")]
public sealed class App : Component
{
    public override Node Render() =>
        AppRouter("/",
            AppRoutes(
                Route("/", () => Home()),
                Route("/settings", () => Settings()),
                Route("/docs/*", () => Docs())));
}

private static Node Home() =>
    <div className="page">
        <h1>Home</h1>
        {Link("/settings", Text("Open settings"))}
    </div>;

private static Node Settings() =>
    <div className="page"><h1>Settings</h1></div>;

private static Node Docs() =>
    <div className="page"><h1>Docs</h1></div>;
using Donkeh.Hosting;
using Donkeh.UILab;
using static Donkeh.UILab.HtmlHelper;
using static Donkeh.UILab.Routing;

[AppRoot(Width = 1000, Height = 700, Title = "My app")]
public sealed class App : Component
{
    public override Node Render() =>
        AppRouter("/",
            AppRoutes(
                Route("/", () => Home()),
                Route("/settings", () => Settings()),
                Route("/docs/*", () => Docs())));
}

private static Node Home() =>
    Div(new() { ClassName = "page" },
        H1(new(), Text("Home")),
        Link("/settings", Text("Open settings")));

private static Node Settings() =>
    Div(new() { ClassName = "page" }, H1(new(), Text("Settings")));

private static Node Docs() =>
    Div(new() { ClassName = "page" }, H1(new(), Text("Docs")));

A factory overload such as Route("/settings", () => Settings()) builds the page only when it matches. The children overload is fine for cheap pages: 

AppRoutes(
    Route("/", Text("Home")),
    Route("/about", Text("About")));
AppRoutes(
    Route("/", Text("Home")),
    Route("/about", Text("About")));

Paths and matching

Routes and pages are compared after normalisation: the path gets a leading slash, duplicate slashes collapse, a trailing slash is removed, and a query string or fragment is dropped. Paths are case-sensitive.

RouteMatches
/Only the root path.
/settingsExactly /settings.
/docs/*/docs and every descendant such as /docs/intro.
/projects/:idOne segment such as /projects/42; captures id=42.
/projects/:id/*/projects/42 and every descendant such as /projects/42/edit; captures id.
*Every path. Put it last if you use it as a catch-all.
aboutNormalised to /about.
Declare static routes before parameterised routes AppRoutes takes the first match. Put /projects/create before /projects/:id, otherwise create is captured as the id value. Put :name routes before broad wildcards for the same reason.

AppRoutes takes the first match in declaration order. For a not-found page, construct the props directly so the fallback is available: 

AppRoutes(
    Route("/", () => Home()),
    Route("/settings", () => Settings()),
    Route("*", () => NotFound()));
using static Donkeh.UILab._;

C<AppRoutes, AppRoutesProps>(new AppRoutesProps
{
    Children =
    [
        Route("/", Text("Home")),
        Route("/settings", Text("Settings"))
    ],
    Fallback = Text("Not found")
});

Reading the path and calling setPage

AppRouter publishes the path and the navigation action, while the matched Route publishes the captured values:

ContextValue
Router.PathThe current normalised path as a string.
Router.RouteValuesThe RouteValues captured by the matched Route.
Router.SetPageAn Action<string> that navigates to a new path.
 
public sealed class SaveButton : Component
{
    public override Node Render()
    {
        var setPage = UseContext(Router.SetPage);
        return <button onClick={() => setPage("/saved")}>Save</button>;
    }
}
using Donkeh.UILab;
using static Donkeh.UILab.HtmlHelper;
using static Donkeh.UILab._;

public sealed class SaveButton : Component
{
    public override Node Render()
    {
        var setPage = UseContext(Router.SetPage);

        return Button(new()
        {
            ClassName = "primary",
            OnClick = () => setPage("/done")
        }, Text("Finish"));
    }
}

A component can also read the current path. It re-renders when the router publishes a new value, because the component sits under the provider: 

public sealed class PathLabel : Component
{
    public override Node Render()
    {
        var path = UseContext(Router.Path);
        return <span className="path">{path}</span>;
    }
}
public sealed class PathLabel : Component
{
    public override Node Render() =>
        Span(new() { ClassName = "path" },
            Text(UseContext(Router.Path)));
}
setPage is not browser navigation The router stores a string. It does not update the URL, push history or intercept the back and forward buttons. A host can persist the current path or feed it into AppRouter through InitialPath. Calling UseContext(Router.SetPage) outside an AppRouter gets the default no-op action.

Route parameters and values

A :name segment captures one path segment. The matched Route publishes the captured values to its content through Router.RouteValues, so any component rendered by that route can read them with UseContext. 

public sealed class ProjectPage : Component
{
    public override Node Render()
    {
        var values = UseContext(Router.RouteValues);
        var id = values["id"] ?? "missing";

        return (
            <div className="page">
                <h1>Project {id}</h1>
            </div>
        );
    }
}

public sealed class App : Component
{
    public override Node Render() =>
        AppRouter("/projects/42",
            AppRoutes(
                Route("/projects", Text("Projects")),
                Route("/projects/create", Text("Create")),
                Route("/projects/:id", () => <ProjectPage />)));
}
public sealed class ProjectPage : Component
{
    public override Node Render()
    {
        var values = UseContext(Router.RouteValues);
        var id = values["id"] ?? "missing";

        return Div(new() { ClassName = "page" },
            H1(new(), Text("Project " + id)));
    }
}

public sealed class App : Component
{
    public override Node Render() =>
        AppRouter("/projects/42",
            AppRoutes(
                Route("/projects", Text("Projects")),
                Route("/projects/create", Text("Create")),
                Route("/projects/:id", C<ProjectPage>())));
}

RouteValues is a read-only set: values["id"] returns string?, values.TryGetValue("id", out var id) avoids the null check, and values.Count / values.Values expose the whole set. Captured segments are URL-decoded. Query strings and fragments are dropped during normalisation, so route values come from path segments only.

Values are scoped to the content returned by the matched Route. A component outside that content sees RouteValues.Empty, and a nested Route replaces the set for its own content. Use /projects/:id/* when the same parameter should also be visible to child pages.

Matching a path manually

Hosts and navigation helpers can resolve route values without rendering a component. Router.TryMatch returns whether the pattern matched and fills a RouteValues; Router.Match returns the values directly (or an empty set). Router.Matches remains the boolean-only helper. 

if (Router.TryMatch("/projects/:id/edit", "/projects/42/edit", out var values))
{
    var id = values["id"]; // "42"
}

var same = Router.Match("/projects/:id", "/projects/42")["id"]; // "42"
var matches = Router.Matches("/projects/:id", "/projects/42");  // true

Both helpers normalise the route and the path before matching, so projects/:id and /projects/42/ work as expected.

Links and active state

Link renders an anchor and calls setPage on click instead of relying on browser navigation. It adds the active class while the target is the current path or an ancestor of it: 

Nav(new() { ClassName = "nav" },
    Link("/", Text("Home")),
    Link("/settings", Text("Settings")),
    Link("/docs", Text("Docs")));

// A link is active on /docs and /docs/intro,
// but the root link is only active on /.

Pass ActiveClassName to change the class, or an empty string to disable it: 

C<Link, LinkProps>(new LinkProps
{
    To = "/settings",
    ActiveClassName = "is-current",
    Children = [Text("Settings")]
});

Useful patterns

PatternApproach
Lazy pagesUse the Route(path, Func<Node?>) overload so page trees are built only when matched.
Section layoutReturn a layout component from a wildcard route, then render AppRoutes again inside it for child pages.
Current page in a headerRead Router.Path in any component under AppRouter.
Programmatic navigationRead Router.SetPage in an event handler or effect; do not call setters during render.
Record pagesDeclare /resource/:id and read UseContext(Router.RouteValues)["id"] in the page component.
Static before parameterisedDeclare /resource/create before /resource/:id; AppRoutes uses the first match.
Not foundSet AppRoutesProps.Fallback, or add a final Route("*", ...).
