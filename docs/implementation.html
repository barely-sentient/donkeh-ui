Implementation for Nerds

The user documentation explains how to build with Donkeh. This area is the other half: how each package works internally, why the boundaries are where they are, which data structures carry the hot path, and what was rejected along the way.

Written from the implementation Each package page now covers the problem it solves, its core data structures, the hot path, the decisions that were difficult, and the limitations that are still open. Start wherever your curiosity points.

Reading order

The list follows the data flow rather than the solution order. Start at the parser if you want the whole pipeline; jump straight to a package if you are investigating one layer.

Donkeh.Parser Tokenizer, rule builders and interned tokens. Donkeh.Data Flat tables, selector records and cascade matching. Donkeh.DataEngine Stream parser and media-condition compiler. Donkeh.LayoutLab Style resolution, layout, text, paint and animation. Donkeh.UILab Components, hooks, reconciliation, routing and HTML helpers. Donkeh.Hosting App model, AppRoot discovery and permissions. Donkeh.Windowing Desktop window loop, OpenGL, input, text and media. Donkeh.Windowing.Android Android activity and permission bridge. Donkeh.Windowing.Browser DOM host and virtual-tree patch protocol. Donkeh.Inspector Hierarchy, styles, performance, animations and deploy. Donkeh.CliTool Project generation, targets and framework resolution.
